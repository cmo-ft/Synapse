# Run 3 truth labels for the Higgs lepton fallback

27 November 2026. This dataset adds EasyJet evidence for reconstructed electrons and muons when the Higgs decay tree leaves their ancestry or pairing unknown. It uses the same events, weights, reconstructed features and five-block ParT as the 27 November Higgs decay-tree run. The updated dataset and its recipe share the name `Run3_test_20261127_higgs_lepton_fallback`. ## How a lepton or jet gets a Higgs label

Each valid electron, muon or jet has two separate truth questions. `ancestryHiggs` asks whether it descends from **any** recorded Higgs. The Higgs pair matrix asks whether **both objects descend from the same Higgs**. A negative pair can therefore contain two descendants of different Higgs bosons, or at least one non-Higgs object. A zero ancestry target is an established nonmember. An unknown target is excluded from its loss. [Dataset builder](../../run_dir/Run3_test_20261127_higgs_lepton_fallback/frozen/recipe/publish.py) · [Training loss](../../run_dir/Run3_test_20261127_higgs_lepton_fallback/frozen/synapse/loss_functions/lepton_objects.py)

| Evidence in an event | Object ancestry | Same-Higgs pair |
|---|---|---|
| The decay tree establishes an answer | Use the tree answer, including a definite negative | Use the tree answer, including a definite negative |
| Unresolved reconstructed e or μ, with any positive EasyJet Higgs mask | Positive, even when several bits are set or the lepton has W or another `partOrigin` | Compare the two masks only when each lepton has exactly one set bit. Equal bits give a positive pair, different bits give a negative pair |
| Zero EasyJet mask on an unresolved lepton | Unknown | Unknown if the tree also leaves the pair open |
| Unresolved jet or pair involving a jet | Use the hard-decay tree evidence | Use the hard-decay tree evidence |
| MET or padding | Excluded | Excluded, as are diagonal entries |

**The decay tree.** We read the children and grandchildren of each recorded Higgs. A reconstructed lepton can match a charged truth daughter of the same flavour and charge within ΔR < 0.1. A jet can match a hard quark or gluon within ΔR < 0.2. We consider all one-to-one assignments that match the largest number of distinct daughters, including competing selected jets outside the stored slots. A label is definite when those assignments agree on its answer. A missing compatible daughter or an incompletely recorded decay can leave an object unknown. An event with both Higgs records explicitly absent gives negative ancestry and pair labels for its physical slots. The same Higgs rule applies to every process. [Frozen decay matcher](../../run_dir/Run3_test_20261127_higgs_tree/frozen/recipe/higgs_decay.hxx) · [Tree label publication](../../run_dir/Run3_test_20261127_higgs_tree/frozen/recipe/publish.py)

For example, in a resolved HH → 4W → 3ℓ + 2j event one Higgs supplies two leptons. The other supplies one lepton and the two jets. Among those five objects there are four same-Higgs pairs and six different-Higgs pairs. The two jets can exchange which W quark they match while their common Higgs remains certain. In a fully resolved WH → 3ℓ event, accounting for the compatible Higgs daughters can exclude the associated-W lepton from the Higgs. The same evidence rule handles an ambiguous WH event by leaving the disputed target open. [Fully matched HH counts and WH example](../../run_dir/Run3_test_20261127_higgs_tree/run_record.md)

**The EasyJet fallback.** The two raw branches are `el_parentHiggsParentsMask` and `mu_parentHiggsParentsMask`. Zero means the decorator recorded no match. A positive mask supplies evidence for binary ancestry. A single set bit also identifies a parent within the decorator's own ordering. We compare two such bits within an event. The decorator orders parents by mass and the stored Higgs decay records order them by pT. The fold's `relationHiggs` branch therefore keeps tree instance IDs only. A fallback pair can be known even when an endpoint has `relationHiggs = −1`. [Fallback implementation](../../run_dir/Run3_test_20261127_higgs_lepton_fallback/frozen/recipe/higgs_labels.py) · [ATLAS parent decorator](https://atlas-sw-doxygen.web.cern.ch/atlas-sw-doxygen/atlas_main--Doxygen/docs/html/d1/d66/classTruthParentDecoratorAlg.html) · [EasyJet Higgs ordering](../../../../easyjet/easyjet/EasyjetHub/src/TruthParticleInformationAlg.cxx)

Two examples motivated this choice. First, the stored H → W → τ branch can end at the τ. Among the 14,122 newly positive fold 1 HH leptons with `partOrigin` other than Higgs, the separate truth-τ audit found a compatible Higgs cascade for 11,530, including 10,952 through W → τ. That audit checks the fallback independently and supplies no training IDs. Second, the small-R jet decorator can match the Higgs direction itself when its selected cascade drops the W daughters. WH event 526514 has a positive jet mask and a recorded H → WW → μ⁺νμ μ⁻ν̄μ decay containing no quarks. The tree definition keeps this jet out of the hard Higgs decay. [Truth-τ audit](../../run_dir/Run3_test_20261127_higgs_tree/tau_fallback_audit.json) · [WH event record](../../run_dir/Run3_test_20261127_higgs_tree/leptonic_higgs_jet_mask_example.json) · [ATLAS cascade settings](https://atlas-sw-doxygen.web.cern.ch/atlas-sw-doxygen/atlas_main--Doxygen/docs/html/d0/dad/namespaceParentDecoratorConfig.html)

**Conflicting evidence.** Before writing a fallback, we require the combined labels to admit at least one assignment to the number of Higgs bosons recorded in the event. We keep every definite tree answer, then maximize the number of compatible binary ancestry additions, then the number of compatible pair additions. Tied choices retain only the additions they all share. In HH event 2847402 (DSID 604422), the tree assigns l2 and l3 to different Higgs bosons. All three leptons carry the same EasyJet bit. We recover l1's Higgs ancestry and leave both l1 pairings unknown. Across the six files, eight HH events required this rule. It withheld six proposed same-Higgs and five proposed different-Higgs labels. All binary ancestry additions survived. ## Which targets the network learns

| Training output | Truth target and eligible objects |
|---|---|
| Main event class | HH signal = 0, other background = 1, external-conversion background = 2. Background conversion uses the analysed ntuple's `is_conv` MC category. Region membership and event class are separate. |
| Three lepton-origin scores | Three independent binary predictions from `partOrigin`. Higgs selects 1, top selects 2, W/Z/diboson selects 3, 4 or 5. Other origins map to 0 in the source. Every valid jet and MET slot contributes target zero to these three losses. Positive and negative lepton weights are balanced within the training fold. Jets and MET have class factor 1. The divisor is the fold-wide weighted mean number of valid slots. |
| Conversion and heavy-flavour scores | Two independent binary targets on reconstructed e and μ. `isConv` selects a nonprompt, non-charge-misidentified candidate with truth origin 5 and truth type 4. `isHF` selects truth origins 25, 26, 27, 29, 32 or 33. |
| Four ancestry scores | Higgs, top, W and Z are independent memberships. A matched H → W → ℓ daughter can be positive for both Higgs and W even when its separate `partOrigin` is W. Positive top masks or a known top instance establish top ancestry. W and Z use identified boson daughters or verified continuum assignments. Explicit evidence can exclude a competing species. A missing match alone leaves the membership unknown. |
| Four symmetric pair matrices | One each for Higgs, top, W and Z. For Higgs, `higgsPairKnown` and `higgsPairSame` store the known and positive bits in the upper triangle. For the other parents both instance IDs must be known. Equal positive IDs mean same parent. Each physical pair enters the loss once, with MET, padding and the diagonal excluded. The predictions from block four feed the attention in block five. |
| WZ recoil | The binary target `isWZ` comes from the process catalog. The classifier averages the scores of eligible same-flavour, opposite-charge lepton-pair hypotheses using transverse recoil, MET, the remaining lepton and jets. Its prediction feeds the event classifier. |

For the origin heads the lepton truth-origin codes are 14 → Higgs, 10 → top, 13 → Z, 12 → W and 43 → diboson. Thus the origin head and ancestry head can legitimately give different answers for the same lepton. The model takes reconstructed observables at application. The dataset carries truth for supervision and evaluation, and the stored EveNet and XGBoost scores serve as benchmarks. [CAF truth definitions](../../../../caf/hhml3l0tau/work/nominal-run3-20261122/source/include/physics.hxx) · [Origin codes](../../../../caf/hhml3l0tau/work/nominal-run3-20261122/source/include/ntuple.hxx) · [Inputs and spectators](../../run_dir/Run3_test_20261127_higgs_lepton_fallback/frozen/recipe/data_config.yaml) · [Model and loss coefficients](../../run_dir/Run3_test_20261127_higgs_lepton_fallback/frozen/recipe/model_config.yaml)

For W, a fully matched HH → 4W event certifies one hadronic W pair among the central jets. When wrong alternatives exist, that true pair and the alternative pairs collectively receive equal weight within the hadronic assignment loss. For continuum WZ, prompt-lepton flavour and charge resolve an unambiguous Z pair. In WZCR only, the strict mass fallback requires matched truth leptons, one same-flavour opposite-charge candidate within 5 GeV of 91.2 GeV and the other more than 15 GeV away. The remaining prompt WZ lepton then has W ancestry. The inherited H → ZZ matcher assigns individual Z IDs for the four-charged-lepton truth topology only. Consequently two quark-matched jets can have established Higgs and Z ancestry while their Z pair target remains unknown. ## Training handoff

Fold 1 uses remainder 0 for training, 2 for validation and 1 for test, with remainders defined by eventNumber % 3. Its training sample has 2,296,499 SR plus ExtConvCR events and 518,851 WZCR events. The staged run uses 50 epochs and batch size 768. Checkpoint selection maximizes the quadrature sum of the Asimov significances in three disjoint HH-efficiency bands, 0–20%, 20–30% and 30–50%, with background MC variance from Σw². [Frozen launcher](../../run_dir/Run3_test_20261127_higgs_lepton_fallback/frozen/recipe/launch.py) · [Working-point metric](../../run_dir/Run3_test_20261127_higgs_lepton_fallback/frozen/synapse/core/working_point_significance.py) · [GPU submission description](../../run_dir/Run3_test_20261127_higgs_lepton_fallback/fold1.sub)

Every row and all 99 branch schemas were checked against the tree-only files. The 96 carried-over branches matched bit for bit. The other three passed independent checks that every previously known tree answer was preserved. A one-epoch CPU integration check used real examples of each fallback, reloaded the best checkpoint and scored validation and test. All 21 Python tests passed, including a comparison of the event-consistency rule against explicit parent assignments. The GPU submission description passed its HTCondor dry run.
